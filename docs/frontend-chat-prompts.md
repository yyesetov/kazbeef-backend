# Чат по базе знаний и страница «База знаний»: задачи для фронтенда

Бэкенд готов. Здесь — что сделать во фронтенд-проекте (`frontend/`, React + Mantine + TanStack Query), по шагам. Каждый шаг — отдельный промпт: копируйте его в ИИ-инструмент целиком, по одному, по порядку. В конце каждого шага есть проверка.

Перед первым шагом приложите к контексту ИИ этот файл целиком: в нём описан контракт API, на который ссылаются промпты.

## Контракт API (справка для всех шагов)

### Публичный чат — без входа, без CSRF

**`GET /public/chat/status`**

```json
{ "enabled": true, "maxQuestionLength": 1000 }
```

`enabled: false` — на сервере не задан ключ ИИ: вопросы принимаются, но ответить модель не сможет (придёт событие `error`).

**`POST /public/chat/stream`**

Тело запроса (JSON):

```json
{
  "question": "Какие СИЗ нужны при дезинфекции?",
  "history": [
    { "role": "user", "text": "предыдущий вопрос" },
    { "role": "assistant", "text": "предыдущий ответ" }
  ]
}
```

- `history` — последние реплики диалога, сервер берёт не больше 6. Можно пустой массив.
- Вопрос: не пустой, не длиннее `maxQuestionLength`.

Ответ — поток Server-Sent Events (`text/event-stream`). События по порядку:

| event | data | смысл |
|---|---|---|
| `sources` | `[{ "id": 1, "title": "Инструкция по ТБ", "heading": "Раздел › Подраздел" }]` | документы, по которым будет дан ответ; пустой массив — в базе ничего не нашлось |
| `delta` | `{ "text": "кусок ответа" }` | приходит много раз, куски склеиваются по порядку; ответ в Markdown |
| `done` | `{}` | ответ закончен |
| `error` | `{ "message": "текст для пользователя" }` | ответ прерван, показать сообщение |

Если в базе ничего не найдено, сразу приходят `sources: []`, одна `delta` с фразой «В базе знаний нет материалов по этому вопросу…» и `done`.

Ошибки до начала потока — обычный JSON:

| код | тело | что делать |
|---|---|---|
| 400 | `{ "error": "Пустой вопрос" }` | показать текст |
| 429 | `{ "error": "Слишком много вопросов подряд…" }` + заголовок `Retry-After` (секунды) | показать текст и сколько ждать |

Пример потока:

```
event:sources
data:[{"id":1,"title":"Инструкция по дезинфекции","heading":"Дезинфицирующие средства"}]

event:delta
data:{"text":"Для дезинфекции "}

event:delta
data:{"text":"нужны респиратор, перчатки и фартук."}

event:done
data:{}
```

### База знаний — только админ (сессия + CSRF, как остальные `/admin/**`)

| Метод и путь | Тело | Ответ |
|---|---|---|
| `GET /admin/kb/formats` | — | `{ "extensions": ["docx","htm","html","markdown","md","pdf","txt"], "maxFileSizeMb": 50 }` |
| `POST /admin/kb/documents` | `multipart/form-data`, поле `files` (один или несколько файлов) | `[{ "name": "a.docx", "id": 7, "status": "processing" }, { "name": "b.js", "status": "rejected", "error": "Формат «.js» не поддерживается…" }]` |
| `GET /admin/kb/documents` | — | массив документов (см. ниже) |
| `GET /admin/kb/documents/{id}` | — | один документ |
| `GET /admin/kb/documents/{id}/markdown` | — | текст Markdown (`text/markdown`); `?download=true` — скачать файлом |
| `PUT /admin/kb/documents/{id}/markdown` | текст Markdown, `Content-Type: text/markdown` | документ |
| `PUT /admin/kb/documents/{id}` | `{ "title": "…", "summary": "…", "tags": ["…"] }` | документ |
| `POST /admin/kb/documents/{id}/reprocess` | — | документ (статус снова `processing`) |
| `DELETE /admin/kb/documents/{id}` | — | 204 |
| `GET /admin/kb/questions?unanswered=true&limit=50` | — | `[{ "id": 3, "askedAt": "2026-11-17 06:35:56+00", "question": "…", "found": false, "documentIds": "[]" }]` |

Документ:

```json
{
  "id": 7,
  "originalName": "Инструкция_ТБ.docx",
  "format": "docx",
  "originalSize": 2633,
  "title": "Инструкция по технике безопасности",
  "summary": "О чём документ, 2–3 предложения.",
  "tags": ["тб", "крс"],
  "status": "ready",
  "error": null,
  "markdownSize": 1112,
  "chars": 1080,
  "chunks": 5,
  "createdAt": "2026-11-17 06:30:00+00",
  "updatedAt": "2026-11-17 06:30:04+00"
}
```

- `status`: `processing` → `ready` или `failed` (причина в `error`). Обработка занимает секунды; пока есть документы в `processing`, список нужно перезапрашивать.
- `title` и `summary` заполняет ИИ после обработки. Пока ИИ не настроен, `title` — имя файла, `summary` пустой.
- Загрузка больше 50 МБ — ответ 413 `{ "error": "Файл больше 50 МБ" }`.

## Шаг 1. Прокси nginx для чата и загрузки файлов

**Зачем.** Чат идёт по адресу `/public/…`, а nginx фронтенда сейчас проксирует только `/api/` и `/admin/`. Кроме того, nginx по умолчанию буферизует ответ — тогда текст ответа придёт одним куском в конце, а не по мере генерации — и не пропускает файлы больше 1 МБ.

**Промпт:**

```
В проекте фронтенда есть nginx-конфиг nginx/default.conf.template (раздаёт статику и проксирует /api/ и /admin/ на ${BACKEND_URL}) и nginx/proxy.inc с общими настройками прокси.

Внеси изменения:

1. Добавь location /public/ с proxy_pass ${BACKEND_URL} и include /etc/nginx/conf.d/proxy.inc — так же, как у /api/. Это публичный чат, ответ идёт потоком Server-Sent Events, поэтому в этом location дополнительно:
   - proxy_buffering off;
   - proxy_cache off;
   - proxy_read_timeout 180s;
   - add_header X-Accel-Buffering no;
   - gzip off;
   Без отключения буферизации текст ответа будет приходить одним куском в конце.

2. В location /admin/ добавь client_max_body_size 200m; — туда загружаются документы базы знаний (до 50 МБ каждый, несколько за раз).

3. В vite.config.ts в server.proxy добавь '/public': BACKEND_URL (так же, как уже сделано для '/api' и '/admin'), чтобы чат работал в режиме npm run dev.

Больше ничего не меняй. Покажи итоговые файлы целиком.
```

**Проверка.** Пересобрать контейнер фронтенда. `curl -N -X POST -H "Content-Type: application/json" -d '{"question":"test","history":[]}' http://localhost:3000/public/chat/stream` — в ответе события `sources`, `delta`, `done`.

## Шаг 2. Клиент API: поток чата и загрузка файлов

**Промпт:**

```
В src/api/client.ts есть функции get, send (JSON с CSRF-токеном, повтор при 403), классы ApiError, AuthError, NetworkError и функция apiUrl из src/config.ts. Типы — в src/api/types.ts, экспорт — через src/api/index.ts.

Нужно добавить две вещи. Приложенный файл docs/frontend-chat-prompts.md содержит контракт API (раздел «Контракт API»).

1. Новый файл src/api/chat.ts — клиент публичного чата.
   - Типы: ChatRole = 'user' | 'assistant'; ChatTurn = { role: ChatRole; text: string }; ChatSource = { id: number; title: string; heading: string | null }; ChatStatus = { enabled: boolean; maxQuestionLength: number }.
   - getChatStatus(): Promise<ChatStatus> — GET /public/chat/status.
   - streamChat(question: string, history: ChatTurn[], handlers: { onSources(s: ChatSource[]): void; onDelta(text: string): void; onDone(): void; onError(message: string): void }, signal: AbortSignal): Promise<void>.
     - POST /public/chat/stream, Content-Type: application/json, тело { question, history }. Без CSRF и без cookie (credentials: 'omit') — эндпоинт публичный.
     - EventSource не подходит (он умеет только GET), поэтому читай поток через fetch + response.body.getReader() + TextDecoder и разбирай SSE вручную: события разделены пустой строкой, в событии строки "event:имя" и "data:json" (data может быть разбит на несколько строк data: — склеивай их через \n). Учитывай, что один кусок из reader может содержать половину события — держи буфер.
     - Если ответ не 2xx — прочитай JSON { error } и вызови onError(error). Для 429 добавь к тексту «Повторите через N с» из заголовка Retry-After.
     - Отмена через signal (AbortError) — это не ошибка: просто выйди без onError.
     - Сетевой сбой — onError('Нет связи с сервером').
     - Если поток закончился без события done и без error — вызови onError('Ответ прервался').
   - Вынеси разбор SSE в отдельную чистую функцию (например, createSseParser(onEvent)), чтобы её было удобно проверить.

2. В src/api/client.ts — функция upload<T>(path: string, files: File[], field = 'files'): Promise<T> для multipart-загрузки в админку: FormData, тот же CSRF-заголовок и та же логика повтора при 403, что у send (вынеси общую часть, не копируй). Content-Type не ставь — браузер сам добавит boundary. Ответ 413 — ApiError с текстом из тела { error }.
   Ещё нужны sendText(path, method: 'PUT', text, contentType) для PUT /admin/kb/documents/{id}/markdown и del(path) для DELETE (оба с CSRF).

Экспортируй новое через src/api/index.ts. Стиль, комментарии и обработку ошибок держи как в существующем client.ts.
```

**Проверка.** `npm run typecheck`. Если в проекте есть тесты (`vitest`) — пусть ИИ добавит тест на разбор SSE: событие, разрезанное на два куска, должно собраться в одно.

## Шаг 3. Состояние диалога (хук useChat)

**Промпт:**

```
Сделай хук src/components/chat/useChat.ts поверх streamChat и getChatStatus из src/api/chat.ts.

Модель данных:
- ChatMessage = { id: string; role: 'user' | 'assistant'; text: string; sources?: ChatSource[]; status: 'streaming' | 'done' | 'error' | 'stopped'; error?: string; notFound?: boolean }.

Хук возвращает: messages, isStreaming, status (ChatStatus из useQuery с ключом ['chat-status'], staleTime 5 минут), send(question), stop(), reset(), retry().

Поведение:
- send: обрезает пробелы; пустой или длиннее status.maxQuestionLength — не отправляет. Добавляет сообщение пользователя и пустое сообщение ассистента со status 'streaming', вызывает streamChat с AbortController.
- history для запроса — последние 6 завершённых сообщений (status 'done') до текущего вопроса, в виде { role, text }. Сообщения с ошибкой и остановленные в историю не идут.
- onSources: записать sources в сообщение ассистента; пустой массив — notFound: true.
- onDelta: дописывать текст. Обновления копить и применять не чаще одного раза за кадр (requestAnimationFrame), иначе при быстром потоке интерфейс тормозит.
- onDone: status 'done'. onError: status 'error' и текст ошибки.
- stop(): abort, у сообщения status 'stopped', уже пришедший текст остаётся.
- retry(): повторить последний вопрос пользователя (удалить последний неудачный ответ).
- reset(): прервать поток и очистить диалог.
- Диалог хранить в sessionStorage (ключ 'kazbeef-chat'), восстанавливать при загрузке; сообщения в статусе 'streaming' при восстановлении считать 'stopped'. Все обращения к sessionStorage — в try/catch (в приватном режиме он может бросать исключения).
- При размонтировании — abort.
- Одновременно идёт только один ответ: send во время потока игнорируется.
```

**Проверка.** `npm run typecheck`.
