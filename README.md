# KazBeef — бэкенд

Система мониторинга эпизоотической ситуации по болезням **КРС и МРС** в Казахстане, странах СНГ и странах — поставщиках мяса. Собирает данные из открытых источников, нормализует их, оценивает риск для Казахстана, рассылает оповещения и отвечает на вопросы посетителей по базе знаний (инструкции, техника безопасности).

Это только API. Интерфейс — отдельный репозиторий `kazbeef-frontend`: его nginx раздаёт страницы и проксирует запросы `/api`, `/admin` и `/public` сюда.

## Что внутри

| Часть | Что делает |
|---|---|
| Сборщики | WAHIS (WOAH), сводки ИАЦ Россельхознадзора, публикации EFSA — по расписанию и вручную |
| Нормализация | болезни, страны и виды животных приводятся к справочникам; одно событие из нескольких источников хранится один раз |
| Риск | балл 0–100 для каждого события: вес болезни, расстояние до границы РК, давность, масштаб, статус, динамика |
| ИИ (Claude) | перевод событий на русский и краткое резюме; описание документов базы знаний; ответы в чате |
| Оповещения | Telegram и e-mail: события в Казахстане, в приграничной зоне 300 км, с высоким риском; ежедневный дайджест |
| Экспорт | Excel, CSV, недельная сводка в PDF |
| База знаний и чат | админ загружает документы (DOCX, PDF, HTML, TXT, MD) → они превращаются в Markdown без картинок → посетители задают вопросы, бот отвечает только по документам |

Стек: Java 21, Spring Boot 3.5, PostgreSQL 16, Flyway, Docker.

Страны наблюдения:
- **соседи:** Казахстан, Россия, Китай, Киргизия, Узбекистан, Туркменистан, Монголия;
- **СНГ:** Армения, Азербайджан, Таджикистан, Молдова;
- **поставщики мяса:** Беларусь, Украина, Бразилия, Парагвай.

Список задаётся в `src/main/resources/application.yml` (`kazbeef.wahis.countries`) и в справочнике `country`.

## Запуск: пошагово

### 1. Что нужно установить

- **Docker Desktop** (Windows, macOS) или Docker Engine с плагином Compose (Linux). Проверка: `docker compose version`.
- **Git**.

Java и Maven ставить не нужно: приложение собирается внутри Docker.

### 2. Скачать проект

```bash
git clone <адрес репозитория> kazbeef
cd kazbeef
```

### 3. Создать файл настроек `.env`

```bash
cp .env.example .env
```

Откройте `.env` и заполните обязательные параметры:

| Параметр | Что указать |
|---|---|
| `DB_PASSWORD` | любой надёжный пароль для базы данных |
| `ADMIN_PASSWORD` | пароль администратора для входа в интерфейс |
| `ADMIN_USERNAME` | логин администратора (по умолчанию `admin`) |
| `KAZBEEF_CONTACT_EMAIL` | ваш e-mail: передаётся источникам данных в заголовке запросов, как требуют их правила |

Файл `.env` не попадает в git — в нём пароли и ключи.

### 4. Запустить

```bash
docker compose up -d --build
```

Первая сборка занимает 3–5 минут: скачиваются зависимости. Поднимаются два контейнера: `db` (PostgreSQL) и `app` (приложение). Структура базы создаётся автоматически при первом старте.

### 5. Проверить, что работает

```bash
docker compose ps
curl http://localhost:8080/actuator/health
```

Ответ `{"status":"UP"}` — приложение готово. Логи: `docker compose logs -f app`.

### 6. Запустить интерфейс

Интерфейс запускается из своего репозитория (`kazbeef-frontend`, см. его README). По умолчанию он открывается на `http://localhost:3000` и ходит в бэкенд на `http://localhost:8080`. Вход — логином и паролем из `.env`.

### 7. Загрузить данные

Сборщики сами запускаются по расписанию (время Алматы):

| Источник | Когда |
|---|---|
| WAHIS | ежедневно в 03:00 |
| ИАЦ Россельхознадзора | ежедневно в 09:15 и 19:15 |
| EFSA | ежедневно в 03:40 |

При первом запуске WAHIS загружает историю за год, ИАЦ — за 90 дней. Чтобы не ждать, запустите сбор вручную: в интерфейсе **Управление → Источники → «Запустить»**, или командой (подставьте логин и пароль):

```bash
# получить CSRF-токен и cookie сессии
curl -c cookies.txt -u admin:ПАРОЛЬ http://localhost:8080/api/csrf
# запустить сборщик (wahis, iac или efsa); ?days=365 — загрузить историю за год
curl -b cookies.txt -u admin:ПАРОЛЬ -H "X-CSRF-TOKEN: <token из ответа>" \
     -X POST "http://localhost:8080/admin/collectors/iac/run?days=365"
```

Сбор ИАЦ за год занимает около 15 минут: между запросами к сайту выдерживается пауза.

## Необязательные возможности

Включаются строками в `.env`, после правки — `docker compose up -d` (пересборка не нужна).

### ИИ: перевод, резюме, чат по базе знаний

```env
ANTHROPIC_API_KEY=sk-ant-...
# модели (по умолчанию claude-opus-5-5); для быстрых и дешёвых ответов — claude-haiku-5-5
KAZBEEF_AI_MODEL=claude-haiku-5-5
KAZBEEF_CHAT_MODEL=claude-haiku-5-5
```

Ключ — в консоли Anthropic: console.anthropic.com → API Keys. Без ключа сервис работает, но без перевода, описаний документов и ответов в чате (поиск по базе знаний при этом работает).

Проверка: `curl http://localhost:8080/public/chat/status` → `"enabled":true`.

### Оповещения в Telegram

1. Создайте бота у @BotFather, получите токен.
2. Добавьте бота в нужный чат и узнайте id чата (например, через @userinfobot или `https://api.telegram.org/bot<токен>/getUpdates`).
3. В `.env`:

```env
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_CHAT_ID=-1001234567890
```

### Оповещения по почте

```env
KAZBEEF_ALERT_EMAIL_TO=vet@example.kz, duty@example.kz
KAZBEEF_ALERT_EMAIL_FROM=kazbeef@example.kz
SMTP_HOST=smtp.example.kz
SMTP_PORT=587
SMTP_USERNAME=kazbeef@example.kz
SMTP_PASSWORD=...
```

Проверка каналов: интерфейс → **Источники → Оповещения → «Проверить»**.

### Адрес интерфейса в оповещениях

```env
KAZBEEF_PUBLIC_URL=https://kazbeef.example.kz
```

## Повседневные команды

| Задача | Команда |
|---|---|
| Запустить / применить изменения `.env` | `docker compose up -d` |
| Пересобрать после обновления кода | `git pull && docker compose up -d --build` |
| Логи приложения | `docker compose logs -f app` |
| Остановить | `docker compose down` |
| Остановить и **удалить все данные** (база, документы базы знаний) | `docker compose down -v` |
| Резервная копия базы | `docker compose exec db pg_dump -U kazbeef kazbeef > backup.sql` |
| Восстановление базы | `docker compose exec -T db psql -U kazbeef kazbeef < backup.sql` |
| Консоль базы данных | `docker compose exec db psql -U kazbeef kazbeef` |

Данные хранятся в томах Docker: `pgdata` (база) и `kbdata` (Markdown-версии документов базы знаний). Для полной резервной копии сохраняйте оба.

Порты по умолчанию: приложение — `8080`, PostgreSQL — `5432`. Изменить: `APP_PORT=8090` и `DB_PORT=5433` в `.env`.

## API

Все пути, кроме `/public/**` и `/actuator/health`, требуют входа. Изменяющие запросы (`POST`, `PUT`, `DELETE`) требуют CSRF-токен из `GET /api/csrf` в заголовке `X-CSRF-TOKEN`.

| Путь | Назначение |
|---|---|
| `POST /api/login`, `POST /api/logout`, `GET /api/me` | вход, выход, текущий пользователь |
| `GET /api/events`, `GET /api/events/{id}` | события с фильтрами, карточка события |
| `GET /api/map` | точки для карты |
| `GET /api/stats/*` | сводка, динамика, разбивки по странам, болезням, видам, источникам |
| `GET /api/reference` | справочники |
| `GET /api/export/events.xlsx`, `events.csv`, `weekly.pdf` | выгрузки |
| `/admin/collectors/**` | состояние и ручной запуск сборщиков |
| `/admin/diseases/**` | справочник болезней |
| `/admin/kb/**` | база знаний: загрузка документов, просмотр и правка Markdown |
| `/admin/system`, `/admin/ai/run`, `/admin/notify/*` | состояние ИИ и оповещений, ручные запуски |
| `GET /public/chat/status`, `POST /public/chat/stream` | публичный чат (без входа, ответ потоком Server-Sent Events) |

Фильтры событий (одинаковые для списка, карты, статистики и экспорта): `countries`, `diseases`, `groups` (`CATTLE`, `SMALL_RUMINANT`, `OTHER`), `sources`, `trust`, `status`, `from`, `to`, `ruminantOnly` (по умолчанию `true`), `q`, `minRisk`.

Подробный контракт чата и базы знаний — в `docs/frontend-chat-prompts.md`.

## Разработка

Структура кода (`src/main/java/kz/kazbeef`):

| Пакет | Содержимое |
|---|---|
| `collector` | конвейер сборщиков и сами сборщики: `wahis`, `iac`, `efsa` |
| `ingest` | запись событий, дедупликация, пересчёт производных полей |
| `normalize` | сопоставление болезней, стран и видов со справочниками |
| `risk` | расстояние до границы РК и балл риска |
| `ai` | перевод и резюме событий |
| `kb` | база знаний: конвертация документов в Markdown, поиск, чат |
| `notify` | оповещения |
| `export` | Excel, CSV, PDF |
| `api`, `admin` | REST-контроллеры |

Схема базы — миграции Flyway в `src/main/resources/db/migration` (`V1…V9`). Уже применённые миграции не меняются: изменения схемы — только новым файлом `V10__…sql`.

**Новый источник данных:** класс, реализующий `collector/Collector.java`, + запись в таблице `source` + расписание в `kazbeef.collectors.<КОД>` в `application.yml`. Образец — пакет `collector/wahis`.

**Сборка без Docker** (нужны JDK 21 и доступ к Maven Central): `./mvnw package -DskipTests`, затем `java -jar target/kazbeef.jar` с переменными окружения из `.env` и `DB_URL=jdbc:postgresql://localhost:5432/kazbeef`.

## Источники данных и ограничения

- **WAHIS** — официальные отчёты стран в WOAH. Россия подаёт туда мало отчётов, Беларусь не подаёт с 2020 года.
- **ИАЦ Россельхознадзора** — ежедневные сводки по зарубежным странам: официальные данные ВОЗЖ (уровень «подтверждено») и сообщения СМИ (уровень «сигнал»). Внутрироссийской ситуации в сводках нет.
- **EFSA** — научные публикации и новости (уровень «аналитика»), без данных о конкретных вспышках.
- **EMPRES-i+, GLEWS+, ProMED-mail** — не подключены: нет открытого доступа к данным.
